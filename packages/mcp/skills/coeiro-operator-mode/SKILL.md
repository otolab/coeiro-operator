# オペレータモード

この Skill は、ユーザーとの作業で COEIRO Operator を音声通知役として使う場合に適用します。音声出力の引数やキュー操作は各ツールの説明を参照し、オペレータの割り当ての考え方は `coeiro-operator-basics` に従ってください。

## 開始時

ユーザーが会話の始まりを告げたら、`operator_assign` でオペレータを割り当てます。キャラクターに `greeting` が設定されていると、ツールが自動で音声キューへ追加します。挨拶を続けて `say` でも読み上げると重複するため、必要がなければ追加発話しません。

## 作業中

発話の共通原則は `coeiro-operator-basics` に従ってください。作業中は、ユーザーに気づいてほしい情報を選んで音声で知らせます。通常の応答や進捗報告を毎回読み上げる必要はありません。

- すぐ終わる作業は音声で知らせません。
- 数分程度の作業は「完了しました」など短く伝えます。
- 長くかかった作業は、何が完了したかを簡潔に伝えます。詳細は通常のテキスト応答に任せます。
- 作業の開始時は、ユーザーの注意を引く必要がなければ音声で知らせません。

## 終了時

ユーザーが作業の終了や感謝を伝えたら、会話を閉じる音声が必要か判断します。発話する場合は、`say`、`wait_for_task_completion`、`operator_release` の順に進めます。

1. 短い別れの言葉を `say` でキューに追加します。`say` は再生完了を待ちません。
2. `wait_for_task_completion` を `{"remainingQueueLength": 0}` で呼び、音声キューの処理を待ちます。
3. 待機が完了したら `operator_release` で割り当てを解放します。解放時に設定済みの `farewell` が自動で発話されることはありません。

待機の完了はキュー処理が終わったことを示しますが、音声が正常に再生された保証にはなりません。待機がエラーまたはタイムアウトになった場合は発話成功と扱わず、`queue_status` でキュー長と処理状態を確認します。idle が確認できるまで解放しないでください。タイムアウト後も内部の待機処理は取り消されないため、待機を重ねないでください。
