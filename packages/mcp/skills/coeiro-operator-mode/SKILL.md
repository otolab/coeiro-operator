# オペレータモード

この Skill は、ユーザーとの作業で COEIRO Operator を音声通知役として使う場合に適用します。音声出力の引数やキュー操作は `coeiro-operator-basics` に従ってください。

## 開始時

ユーザーが会話の始まりを告げたら、`operator_assign` でオペレータを割り当てます。キャラクターに `greeting` が設定されていると、ツールが自動で音声キューへ追加します。挨拶を続けて `say` でも読み上げると重複するため、必要がなければ追加発話しません。

## 作業中

音声は、ユーザーに気づいてほしい情報を伝えるために使います。通常の応答や進捗報告を毎回読み上げる必要はありません。

- すぐ終わる作業は音声で知らせません。
- 数分程度の作業は「完了しました」など短く伝えます。
- 長くかかった作業は、何が完了したかを簡潔に伝えます。詳細は通常のテキスト応答に任せます。
- 作業の開始時は、ユーザーの注意を引く必要がなければ音声で知らせません。

## 終了時

ユーザーが作業の終了や感謝を伝えたら、会話を閉じるための音声が必要か判断します。音声で伝える場合は、次の順に進めます。

1. 短い別れの言葉を `say` でキューに追加します。`say` の応答は再生完了を待ちません。
2. `wait_for_task_completion` を `{"remainingQueueLength": 0}` で呼びます。これは個別の `say` タスクではなく共有キュー全体を対象にし、キューが空で処理中タスクもない状態まで待ちます。
3. `queue_status` でキュー長が0、処理状態が待機中であることを確認してから `operator_release` を呼びます。どちらかを確認できなければ release せず、待機を続けます。`operator_release` は割り当てを解放するだけで、設定された `farewell` は発話しません。

`say` でキャラクターを指定しない場合、音声タスクを処理するときの現在の割り当てが使われます。キュー処理の前に release すると割り当てがなくなり、既定キャラクターが使われる可能性があるため、release より先にキューを空にします。

待機がタイムアウトした場合は完了扱いにせず、`queue_status` を確認します。キュー長が0で処理中タスクもなければ release に進めます。タスクが残っている、または処理中なら再度待ってください。待機ツールの呼び出しに失敗した場合も同様に状態を確認し、キューが空で処理中でないと確認できるまでは release しません。状態を確認できないままなら、別れの発話やキュー完了を確認できなかったことを通常の応答で伝えます。

待機と `queue_status` が確認するのはその時点の共有キューの状態です。待機ツールはキューを予約・ロックしないため、別の呼び出し元が同じサーバーへ並行してタスクを追加する場合、release まで処理が止まっていることは保証できません。

待機の完了が示すのは音声キューの処理終了までで、別れの音声が正常に再生されたことまでは保証しません。非同期タスクのエラーはログに記録されますが、待機ツールの結果には含まれません。完了を確認した場合も、実際に音声が届いたとは断定しないでください。
