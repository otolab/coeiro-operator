# COEIRO Operator の基本

この MCP サーバーは、日本語テキストを音声で読み上げます。音声を使う場面や、オペレータの運用方法はこの Skill と `coeiro-operator-mode` に従ってください。

## 日本語を読み上げる

`say` に `speechText` を渡します。発話は音声キューに追加され、ツールは再生完了を待たずに応答します。

- `characterId`: キャラクターを直接指定します。指定すればオペレータの割り当ては不要です。
- `rate`: 数値は話速（WPM、50〜400）、`"x1.2"` のような文字列は倍率（0.5〜2.0）です。省略すると話者固有の速度になります。
- `styleName`: スタイル名またはスタイルIDです。省略すると既定のスタイルを使います。

`characterId` を省略した場合は、現在のオペレータの音声を使います。オペレータも未割り当てなら、`operator_assign` を実行するか、`characterId` を指定してください。

## オペレータを使う

オペレータは MCP クライアントの会話単位ではなく、サーバーが認識する端末セッション単位で割り当てられます。同じキャラクターを別セッションで同時に使うことはできません。予約は既定で4時間未使用のまま経過すると解放され、`say` の利用で延長されます。

- `operator_assign`: キャラクターを割り当てます。`characterId` を省略すると自動選択し、必要なら `styleName` でスタイルを指定できます。キャラクターに `greeting` が設定されている場合、割り当て時にその挨拶が音声キューへ追加されます。再生完了は待ちません。
- `operator_status`: 現在の割り当てを確認します。
- `operator_available`: 利用可能なキャラクターを確認します。
- `operator_styles`: キャラクターの基本情報とスタイル一覧を確認します。`characterId` を省略すると現在のオペレータを対象にします。
- `operator_release`: 割り当てを解放します。解放時に `farewell` は発話されません。設定に値があっても、この MCP ツールはそれを音声キューに追加しません。

## 音声キューを確認・制御する

- `queue_status`: 音声キューの状態を確認します。
- `wait_for_task_completion`: 個別のタスクIDではなく、サーバーの音声キュー全体を対象に待ちます。既定の `remainingQueueLength: 0` は、キューが空になり、処理中のタスクもなくなるまで待機します。0より大きい値では処理中タスクが残っていても待機が解除されることがあります。
- 呼び出し開始時点でキュー長が指定した残数以下かつ処理中でない場合（既定値 `0` なら idle）、待機ツールは「待機対象のタスクがありません」と返し、音声側の待機処理を呼びません。そのため、過去のタスク失敗が蓄積されていても、この呼び出しでは検出・消去されず、後の実際の待機で表面化することがあります。
- 早期 return にならず実際に待機する場合は、待機条件に達した時点で蓄積エラーのうち最初のものがツール呼び出しのエラーとして伝播します。`queue_status` にはエラー一覧が出ないため、状態確認だけでタスクの成功までは判断できません。いずれの場合も、キューが空であることは音声が正常に再生された保証にはなりません。
- 待機の既定タイムアウトは30秒です。タイムアウトすると現在のキュー状態を含む警告が通常のツール結果として返りますが、内部の待機処理は取り消されず、キューが条件を満たすまで残ります。待機を重ねると内部の待機が増えるため、タイムアウト後は再度待機せず、`queue_status` を繰り返し確認してください。キューが空で処理中タスクもない状態になれば、キュー処理が終わったことは確認できますが、音声の成功は確認できません。
- `queue_clear`: 待機中の音声タスクを削除します。処理中の音声は止まりません。`taskIds` を指定すると対象を絞れます。
- `playback_stop`: 再生中の発話を停止します。現在のチャンクは最後まで再生され、次のチャンクから止まります。待機中のタスクは削除しません。

ここでいうタスクIDと待機処理は COEIRO Operator 内部の音声キューの仕組みです。MCP Tasks protocol とは別です。
